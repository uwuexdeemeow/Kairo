# Kairo
Kairo takes its name from kairos, the ancient Greek word for the right or opportune moment. It's a desktop productivity hub, and at its heart is the **command palette**: opening Kairo, from the Start menu, Spotlight or a launcher, or pressing its shortcut, brings up the palette, which opens apps, answers questions about your time and runs Kairo's actions. Its first app is **Chrono**, after chronos, kairos' partner word for clock time: a screen time tracker that quietly runs in the background, records which apps and sites you use, and turns that into clear insights about when you focus best and where your time slips away. Kairo also has a **dashboard**, a small window with a Home tab of tiles for its apps and a Settings tab for everything that belongs to Kairo as a whole. Chrono opens from its own Start menu entry (Windows) or app menu entry (Linux), the tray or menu bar, the dashboard and the palette. All data stays on your device. Kairo is built to grow into a single home for everyday tools, with more apps, like a password safe, to come.

## Chrono, the screen time tracker

Chrono runs inside Kairo in the system tray and samples the foreground window once a second. Consecutive samples in the same window become a **session** stored in a local SQLite database (`%APPDATA%\com.kairo.app\kairo.db`). Closing the window keeps tracking, and lets the window go entirely, so Kairo idles in the tray without a web view; use the tray menu to pause or quit. Clicking the tray icon (Windows and Mac; Linux trays don't report clicks, so use the menu) opens the dashboard, and the menu holds **Open dashboard**, **Open Chrono**, **Check for updates**, **Command palette**, **Pause tracking** and **Quit Kairo**.

The **dashboard** (`dashboard.html`, `src/dashboard.ts`) is its own window. Home has a tile for Chrono (today's time on screen and productive share, or "Paused", with Open and Settings) and one for the command palette (its shortcut, with Open). Settings holds what's Kairo-wide: Appearance, the palette's shortcut and options, starting at sign-in, Your data (CSV export, backup and restore), Combine computers and Updates, plus an App settings row that opens Chrono's own settings. Chrono's Settings page keeps only its own: Goals, Privacy, Projects, Calendar, Browser extension, Focus nudges, Evening summary, Focus blocking, Breaks and Demo data, with a link to Kairo's settings. The palette reaches both with **Dashboard** and **Kairo settings**. Launching Kairo with `--dashboard` opens the dashboard (`--palette`, or no argument, opens the palette; `--chrono` opens Chrono; `--minimized` starts quietly), including when a second launch reaches the running copy.

```
collector thread ──► SQLite (sessions, categories) ──► analysis ──► dashboard
 (Win32 foreground                                     (Rust)       (Vite + TS)
  window + idle time)
```

- **Collector** (`src-tauri/src/collector.rs`): foreground app, window title and idle detection. Keyboard, mouse and Xbox-compatible controller input all count as activity. Idle starts after 2 minutes without input (30 minutes on video sites, so watching isn't counted as being away). Sleep and lock screen end the current session.
- **Classification** (`src-tauri/src/classify.rs`): readable app names, sites guessed from browser titles, and default productive, neutral and distracting categories. Users can override any category in the app. Games are named after their install folder (`steamapps\common\THE FINALS` → THE FINALS).
- **Goals** (`src-tauri/src/goals.rs`): a daily productive target, a cap on distracting time and per-app or per-site limits, shown on Today with a streak. A notification goes out at 80% of a limit, when it's passed, and when a target is reached, each at most once a day. The same two goals can be set for a week, Monday to Sunday, shown on Week with a streak of weeks, and notified at most once a week. A limit can also be hard ("Block" beside it in Categories): once passed, its app is minimized behind the blocked window and its site blocked by the extension until midnight, focus session or not, with "Allow 5 minutes" still there. Games are never cut short by a limit; they only get its notification.
- **Browser extension** (`extension/`, `src-tauri/src/browser.rs`): a small Manifest V3 extension for Brave, Chrome and other Chromium browsers that reports the active tab's domain to a listener on `127.0.0.1:47613`, so sites are exact rather than guessed from titles. It ships inside the installer; Settings opens its folder for **Load unpacked**. Only the hostname is sent, and only requests from an extension are accepted. On Windows and a Mac, Kairo reads the site itself as well, so there the extension is needed only to block sites: on Windows from the address bar of Chrome, Edge, Brave, Vivaldi, Opera and Firefox through UI Automation, as a screen reader would (`platform/uia.rs`), once a second and only while the extension isn't reporting; it skips the bar while you type in it, and private windows are recognised from their titles. Linux browsers don't describe themselves to other apps unless a screen reader is on, so there the extension is what makes sites exact.
- **Focus sessions and breaks** (`src-tauri/src/focus.rs`): sessions of 5 to 240 minutes, with an optional label, from the Focus view, the sidebar or the palette. They can be paused (pauses don't count as focus), extended or ended early, and the Focus view shows today, this week and all-time totals with a history of recent sessions. A distraction that holds the screen for 30 seconds mid-session gets a nudge, and sessions show on the Today timeline and the Week view. A break reminder follows a long unbroken stretch at the screen (90 minutes by default); 5 minutes away resets it.
- **Tasks** (`src-tauri/src/tasks.rs`, `src/tasks.ts`): a to-do list on the Focus page. Each task's Start begins a focus session on it, and its row shows the focus time its sessions add up to on this computer. The palette starts sessions on tasks too: `focus 50 essay` counts for an open task whose title matches, `tasks` lists them (Enter starts 25 minutes, Ctrl+Enter marks done) and `task buy milk` adds one. The list travels to combined computers as one shared choice, by random ids that sessions point at.
- **Scheduled focus** (`src-tauri/src/schedule.rs`): on the Focus page, slots that start a focus session on their own, like weekdays 9:00 for 3 hours. A slot starts once on each of its days, when someone is at the computer (input in the last 2 minutes), no session is running and they're in neither a game nor a calendar meeting, and lasts to the end of its window, so arriving late gives a shorter one; ending it early keeps it off until its next day, and a window running past midnight belongs to the day it began. Blocking, launcher closing and strict mode apply as for any session. A slot can block its own list instead ("Only these", picked from the apps and sites Kairo has seen): while it runs, just those are blocked and everything else is let through, Kairo and the system's own apps still never; a session whose slot has gone blocks as usual. Lists can also be saved by name under Block lists (`src-tauri/src/lists.rs`), like Social or Games: a slot can use one instead of its own, and sessions started by hand (the Focus page, the sidebar, the palette) block the list chosen there, or the one their label names ("focus 50 social"). Slots and sessions point at a list by name, so renaming one takes them along, and the lists travel to combined computers and come back with a backup. The schedule, lists included, is shared between combined computers as one choice.
- **Time away** (`src-tauri/src/away.rs`): half an hour or more idle on this computer shows on Today once you're back, asking what it was: a meeting, a call, a break or something else. Labelled, it counts as time under that name (`app:away-meeting` and so on, meetings and calls productive and the rest neutral by default, changeable in Categories); dismissed, it's not asked about again.
- **Projects** (`src-tauri/src/projects.rs`): projects with keywords, set in Settings, gather time across apps: a stretch belongs to the first project with a keyword in its window title or site, so "kairo" collects a VS Code folder, a GitHub repository and a terminal. Each project can have a weekly target (Settings, beside its keywords), which counts as a weekly goal: a bar under Goals this week on Week, a notification once it's reached, and a place in the weekly streak, the month's count of weeks that met their goals and the palette's "goals". Projects show on Today and Week (week or month), where clicking one takes its time apart: a bar an hour for a day or a day for a week or month, the apps and sites it came from and the window titles that matched, so it's easy to see whether the keywords catch the right things. They can be asked about in the palette ("kairo this week", with the change from last week and a bar a day), follow the sidebar's choice of computers, travel between combined computers and come back with a backup. Titles hidden by a privacy rule can't match; their sites still can.
- **Calendar** (`src-tauri/src/calendar.rs`): one or more private calendar addresses (iCal; Google's "secret address", Outlook's published calendar, iCloud's public share) in Settings, read every half hour, two weeks either side of now, and only read. Recurring events are expanded with their exceptions, time zones and moved occurrences (the `rrule` crate); all-day, cancelled and "free" events don't count. Time away during a meeting labels itself "Meeting" under its title, scheduled focus waits for a meeting to end like a game, and the palette answers "next meeting".
- **Focus blocking** (`src-tauri/src/blocking.rs`): during a running (not paused) session, a distracting app in front is minimized behind a small Kairo window offering **Back to work**, **Allow 5 minutes** or **End session**; game launchers (Steam, Epic, Riot, Battle.net, EA, Ubisoft, GOG) are closed; and the browser extension swaps distracting sites for a blocked page. What counts is the category unless Categories says **Always block** or **Never block**. Windows doesn't let Kairo minimize programs running with more rights than it has, which includes many games with anti-cheat. **Strict mode** (off by default) makes ending a session early or allowing something blocked wait 30 seconds and then ask for confirmation, everywhere those can happen, and keeps the blocking settings fixed until the session ends.
- **Command palette** (`src-tauri/src/palette/`): a global shortcut (Ctrl+Space by default, Option+Space on a Mac, changeable in Kairo's settings) opens a small window over anything, or the tray's **Command palette** item, which shows the shortcut. The shortcut does nothing while a game or other full-screen app is in front, so it can't steal keys mid-game, unless Kairo's settings let it open over them; the tray item opens it there either way. On Windows it's drawn natively with Direct2D and DirectWrite (`native.rs`) rather than a web view, so it opens instantly and costs a few megabytes; on macOS and Linux it's a small page in the system's web view (`web.rs`, `src/palette.ts`), kept for ten minutes after use. Both show what the same search finds (`search.rs`). It opens installed apps, ranked by how much you use them: on Windows everything in the Start menu's All apps list, Store apps and the games Steam, Riot and others add included (`platform::start_apps`); on a Mac, app bundles; on Linux, desktop entries. It jumps to Kairo's pages and to days written the way people say them ("yesterday", "last tue", "14 oct"), with a glance at that day; answers questions about time ("finals this week", "youtube today", "slack last month") with a card of the total, the change from the period before, a bar a day against the daily limit and what stands out, plus rows to change the limit or copy the answer (`cards.rs`); and starts focus sessions ("focus 50 essay"), showing first when the session ends, what it blocks, what happens to game launchers and whether strict mode is on. With nothing typed it suggests a focus session, limits passed today and today's apps. It also exports tracked time, backs up and restores (each through the system's file dialog, reported in a notification), says how the weekly goals stand ("goals"), and opens the focus schedule.
- **Look**: a light and a dark palette, following Windows or chosen in Kairo's settings, with the window frame to match. Apps show their real icons, read from their program files (`platform::icon_png`); sites show a letter badge.
- **Patterns**: averages per active day, insights on when distraction peaks and when focus sessions finish, an average day by hour, a weekday-by-hour heatmap, and the top apps and sites over 7, 14 or 30 days.
- **Weekly, monthly and yearly recaps** (`src-tauri/src/recap.rs`): the Week view compares Monday to Sunday with the week before, day by day, with the top apps, projects, goal days and limits passed. Its Week / Month / Year switch shows a whole month the same way against the month before, with a bar a day and how many of its finished weeks met the weekly goals, or a whole year against the year before, with a bar a month (clicking one opens that month) and its best month. A summary notification goes out on Sunday evening for the week, from 10am on the 1st (or the first day at the computer in the month's first week) for the month before, and the same way in early January for the year before.
- **Weekly notes** (`src-tauri/src/notes.rs`): a Notes block at the foot of Week, "What went well" and "What to change", kept for each week (any past week too) and saved when a field is left. Month and Year list their weeks' notes, each opening its week. The Sunday recap ends by pointing to them. Notes travel to combined computers, one shared choice a week, and come back with a backup.
- **Evening summary** (`src-tauri/src/evening.rs`): off unless turned on in Settings; once a day at a set time (9pm by default), while someone is at the computer, a notification with the day's productive and distracting time, goals met, focus sessions and the app that took the most time. Days with under half an hour tracked are skipped.
- **Privacy** (`src-tauri/src/privacy.rs`): per-app and per-site rules to record normally, hide window titles or not record at all (password managers are off by default, private browser windows never keep titles), deleting the last hour, a day or everything, and an optional history limit. Deleted rows are overwritten on disk (`secure_delete`).
- **Your data** (`src-tauri/src/backup.rs`): Kairo's settings export tracked time as a CSV (date, start, end, minutes, app, site, category, title; values that would read as spreadsheet formulas are kept as text), and backs up everything to one `.kairo` file, a consistent copy of the database taken while Kairo runs. Restoring one replaces history, categories, limits and settings, keeping where programs live and the palette shortcut as they are on this computer, saves what was there as `kairo-before-restore.kairo` in the data folder first, and restarts Kairo. Backups restore across Windows, Mac and Linux, since apps share names on each.
- **Combine computers** (`src-tauri/src/sync.rs`): with a folder that a cloud drive syncs (OneDrive, Dropbox, iCloud Drive, Syncthing) chosen in Kairo's settings on each computer, every computer keeps its tracked time in `Kairo computers/<its id>/`, one small SQLite file per day, rewritten only when that day changed, and reads the others' in every 5 minutes, tagged with where it came from (`sessions.device`). Today, Week, limits and recaps then add up every computer; this computer's privacy rules and history length apply to the time it reads in, and history deleted on one computer leaves the others. There's no server. The categories, limits, goals, focus blocking and recording rules the user sets are shared as well (`choices.json`, `shared_choices`): each change carries when it was made and the latest wins everywhere, while choices from before combining count as oldest, so they fill gaps but never undo a newer choice. Focus sessions stay per computer. While several computers are combined, a switch in the sidebar shows everyone's time, this computer's or another's on Today, Week and Patterns; goals and limits always count every computer. Stopping takes this computer's folder away, so the others drop its time too.
- **Analysis** (`src-tauri/src/analysis.rs`): focus blocks, context switches, an hour-of-day and weekday breakdown, and insights such as *"You lose focus most after 10pm"*, *"Your sharpest hours are 9–11am"* and *"Distractions often start right after Slack"*. Each insight only appears when there's enough data behind it.

### Development

Requirements: Rust (MSVC toolchain), Visual Studio C++ build tools with the Windows SDK, and Node 18+.

```sh
npm install
npm run tauri dev      # run the app
npm run tauri build    # installer in src-tauri/target/release/bundle
cd src-tauri && cargo test
```

Run builds from PowerShell or cmd. In Git Bash, `/usr/bin/link` shadows the MSVC linker.

#### macOS (preview)

Tracking, idle time, icons, focus blocking and the command palette also work on a Mac (`platform::mac`). Mac apps go by their bundle name and share categories with their Windows twins (Google Chrome.app counts as `chrome`). Window titles need **Screen Recording** access, which Kairo asks for on first launch. Sites don't: Kairo asks Safari, Chrome, Brave, Edge, Vivaldi and Arc for the front tab's address through Apple Events once a second (`browser::spawn_scripted`), and macOS asks once per browser whether that's allowed; the browser's own answer wins over the extension's, which may be about another browser. Chromium browsers say when a window is incognito, and those sites aren't kept; Safari doesn't, so its private windows are recognised only from their titles. The extension is still what blocks sites during focus sessions. Firefox and Opera don't answer, so Kairo reads their address bar through the Accessibility API instead (`platform/mac/ax.rs`), while the extension isn't reporting; macOS asks once whether Kairo may (Privacy & Security → Accessibility). Instead of being minimized, blocked apps are hidden. Kairo lives in the menu bar: it shows in the Dock and the app switcher only while its window is open.

The macOS build workflow runs the tests on a Mac and keeps a `.dmg` with each run (Actions → macOS build → Artifacts); releases include one too, and Mac copies update themselves like Windows ones. It's only ad-hoc signed, without an Apple Developer ID, so after copying Kairo to Applications, run `xattr -cr /Applications/Kairo.app` once before opening it.

#### Linux (preview)

The command palette, app and site tracking, focus sessions with blocking, and goals work on Linux, with apps tracked, minimized and closed through X11 and `/proc` (`platform.rs`), and app icons come from the desktop entry that runs each program. Wayland doesn't let apps see each other's windows, so on GNOME's Wayland session Kairo installs a small GNOME Shell extension of its own (`gnome-extension/`, `platform/gnome.rs`) that tells it which window is in front and minimizes blocked ones; GNOME turns it on at the next login, and idle time comes from GNOME too. On KDE Plasma's Wayland session, Kairo loads a KWin script (`kwin-script/`, `platform/kde.rs`) that reports the window in front back to it over the session bus, and idle time comes from Plasma's screen locker. On other Wayland desktops Kairo sees only apps running through XWayland, as most games do, and never counts as idle. Game controllers keep Kairo from counting time as idle on every build. Windows games under Wine or Proton go by their `.exe`, so they share names, categories and limits with Windows. The palette's shortcut works on X11. Wayland doesn't let apps listen for keys, so there Kairo hands the shortcut to the desktop: on GNOME it becomes one of GNOME's custom keyboard shortcuts running `kairo --palette`, and on KDE Plasma a global shortcut Plasma tells Kairo about. On other Wayland desktops, add a shortcut in the keyboard settings that runs `kairo --palette` (which also works anywhere else, from a launcher). The Linux build workflow runs the tests on Ubuntu and keeps an AppImage and a `.deb` with each run; releases include both, and both update themselves (the `.deb` asks for your password to install).

To try the insights without waiting weeks, go to **Categories → Load demo data**. Demo rows are flagged and can be cleared on their own.

`tauri build` signs the update bundle, so a local build needs the signing key in the environment:

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content -Raw "$env:USERPROFILE\.tauri\kairo.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""
```

### Releasing

Installed copies update themselves from GitHub Releases: they check a minute after launch and every 6 hours, and Kairo's settings has **Check for updates**. To ship a version, bump `version` in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and `package.json`, then push a matching tag:

```sh
git tag v0.3.0 && git push origin v0.3.0
```

The Release workflow builds, signs and publishes the Windows installer, then a universal Mac app (`.dmg`, plus the update bundle), then a Linux AppImage and `.deb`, with the `latest.json` the app reads. It signs with the `TAURI_SIGNING_PRIVATE_KEY` repo secret, a copy of `%USERPROFILE%\.tauri\kairo.key`. Keep a backup of that key: without it, installed copies can't verify new updates and have to be reinstalled by hand.
